# Codex Task: AI-Generated Visual Identity for Life Museum Exhibits

## 1. Project Context

I am building a full-stack web application called **Life Museum**.

The concept is:

> A museum of your ordinary moments. Every moment has a story.

Users can write down personal memories, and AI transforms them into museum-style exhibits.

The application currently uses:

- **Frontend:** React + Vite (JavaScript / JSX, NOT TypeScript)
- **Backend:** Node.js + Express
- **Database:** PostgreSQL
- **ORM:** Prisma
- **AI:** Google Gemini using `@google/genai`
- **Authentication:** Email/password authentication using bcrypt and express-session
- **Session storage:** PostgreSQL using connect-pg-simple

The frontend and backend are in separate folders:

- `client/`
- `server/`

The backend runs on port 3000, and the Vite frontend communicates with it through the `/api` proxy.

The existing application already supports:
- User registration and login
- Session-based authentication
- Creating AI-generated exhibits from user memories
- Saving exhibits in PostgreSQL
- Retrieving a user's own exhibits
- Displaying a gallery of saved exhibits

The existing Exhibit model contains fields such as:
- `id`
- `originalText`
- `title`
- `subtitle`
- `description`
- `tags`
- `createdAt`
- `updatedAt`
- `userId`

**Important:** Before changing anything, inspect the actual repository and understand its current implementation. Do not assume that every detail in this description exactly matches the latest code.

## 2. New Feature: AI-Generated Exhibit Visual Identity

I want each generated exhibit to have its own visual identity.

Instead of displaying every exhibit using the same card design, I want the application to generate a visual style related to the user's original memory.

The style should reflect the memory's:
- Emotion
- Mood
- Atmosphere
- Themes
- Overall feeling

For example:

**Memory A:**

"I remember walking home with my friends after a long day. We were tired, but we kept laughing about silly things. I wish those evenings could last forever."

Possible visual identity:
- Mood: Nostalgic
- Palette: Warm, dusty pink, soft cream
- Font: Serif
- Border: Thin solid
- Decoration: Small stars
- Layout: Editorial

**Memory B:**

"I spent the afternoon sitting beside the window, watching the rain. I made some tea and enjoyed having absolutely nothing to do."

Possible visual identity:
- Mood: Peaceful
- Palette: Sage green, muted cream
- Font: Serif
- Border: Subtle
- Decoration: Rain-inspired lines or minimal shapes
- Layout: Minimal

These are examples, not fixed rules.

The goal is for the AI to interpret the memory and choose an appropriate visual identity.

## 3. Important Design Principle

I do NOT want completely arbitrary CSS generated by AI.

Instead, implement a controlled design system.

The AI should return predefined identifiers, and the frontend should map those identifiers to actual CSS styles.

For example, the AI might return:

```json
{
  "mood": "nostalgic",
  "themes": ["friendship", "evening", "memories"],
  "styleConfig": {
    "palette": "warm",
    "font": "serif",
    "border": "thin-solid",
    "decoration": "stars",
    "layout": "editorial"
  }
}
```

The frontend should map these values to predefined styles.

Do not allow the AI to return arbitrary CSS, HTML, font URLs, or executable code.

All style identifiers must be validated against allowed options on the backend.

If the AI returns an invalid style, use a safe default rather than crashing.

## 4. Design System Requirements

Create a reusable design system with the following options.

### Color palettes

Start with approximately five palettes:

- Warm: dusty pink, peach, cream, brown
- Calm: sage green, muted green, cream
- Dreamy: lavender, pale blue, soft purple
- Bright: yellow, orange, warm cream
- Minimal: off-white, beige, charcoal

The exact colors can be adjusted to create a cohesive visual experience.

### Fonts

Start with three font categories:

- Serif
- Sans-serif
- Handwritten

Use locally available fonts or appropriately loaded fonts. Avoid adding unnecessary dependencies.

Make sure readability is prioritized.

### Borders

Start with three options:

- None
- Thin solid
- Dashed or decorative

### Decorations

Start with four options:

- None
- Stars
- Dots
- Organic shapes or simple botanical elements

Decorations should be subtle and should not interfere with text readability.

### Layouts

Start with four options:

- Minimal
- Editorial
- Scrapbook
- Poster

Each layout should have a recognizable visual difference while keeping the same core information.

### Size and responsive constraints

The cards must remain within controlled dimensions.

Suggested starting values:

- Width: approximately 280–360px
- Minimum height: approximately 220px
- Maximum height: approximately 340px
- Title: maximum 2–3 lines
- Description: maximum 4–5 lines
- Tags: display a maximum of 3–4 tags

Use responsive CSS so cards work on desktop, tablet, and mobile.

Do not let long text break the layout.
